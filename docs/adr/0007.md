# 0007 — Idempotency generik + offline recovery

## Status
Accepted

## Konteks
Retries dan jaringan offline berpotensi mengulang transaksi, terutama saat kasir menutup penjualan dari perangkat yang offline.

## Keputusan
Setiap operasi penting memakai idempotency key, request hash, dan replay 200 + replayed:true; server juga mendukung outbox dan conflict recovery untuk offline sync.

## Konsekuensi
Menurunkan duplikasi transaksi, tetapi membutuhkan diskusi klarifikasi tiap endpoint yang kritikal.

## Alternatif yang ditolak
Mengandalkan retry naif atau key yang hanya ada di client tanpa server validation.
